# Log Analyzer

構造化されたログファイルを読み込み、ログレベルを自動判定し、不正なログ行を分離しながら、解析結果をCSVへ出力する小型ログ解析ツールです。

このプロジェクトは、Pythonの実務力を高めるために、ファイル処理・文字列処理・例外処理・関数分割・テスト・Git/GitHub運用を組み合わせて作成しています。

## 主な機能

* テキストログを1行ずつ読み込み
* 各ログ行からログレベルを自動取得
* ログレベルごとにログを抽出・表示
* `DEBUG`など、事前に決めていないログレベルにも対応
* 形式が不正なログ行を正常ログと分離
* 入力ファイルが存在しない場合のエラー処理
* 正常ログ・不正ログをCSVへ出力
* `pytest`による自動テスト

## 想定ログ形式

このツールでは、正常なログ行が以下の形式であることを前提としています。

```text
YYYY-MM-DD HH:MM:SS LEVEL message
```

例：

```text
2026-09-11 10:00:00 INFO Application started
2026-09-11 10:01:00 ERROR Failed to connect database
2026-09-11 10:02:00 WARNING Response is slow
```

空白で分割したときの3番目の要素をログレベルとして扱います。

例えば、

```text
2026-09-11 10:03:00 ERROR Failed to read INFO config
```

というログは、メッセージ本文に`INFO`が含まれていても、ログレベルは`ERROR`として判定されます。

## 不正ログの扱い

ログレベルを取得するために必要な要素数を満たしていない行は、不正ログとして扱います。

例：

```text
broken log
```

不正ログは通常のログ解析対象から除外しますが、破棄はせず、別データとして保持します。

そのため、一部に壊れたログ行が含まれていても、残りの正常ログについては解析を続行できます。

正常ログについては、CSV保存時にも各ログ行からログレベルを取得しています。

## 主な関数

### `load_logs(file_path)`

ログファイルを読み込み、正常ログ・ログレベル・不正ログに分けます。

正常時の戻り値：

```python
logs, unique_levels, invalid_logs
```

入力ファイルが存在しない場合：

```python
None, None, None
```

を返します。

### `get_level(log)`

1行のログからログレベルを取得します。

例：

```python
get_level(
    "2026-09-11 10:01:00 ERROR Failed to connect database"
)
```

戻り値：

```text
ERROR
```

形式が不正なログの場合は、

```python
None
```

を返します。

### `get_level_logs(logs, level)`

指定したログレベルと一致するログだけを抽出して返します。

ログ行全体に文字列が含まれているかではなく、実際のログレベル欄を確認して判定します。

### `save_results(file_path, logs, invalid_logs)`

正常ログと不正ログをCSV形式で保存します。

すべてのテストを実行する場合：

```powershell

```

現在、以下をテストしています。

* 正常ログからログレベルを取得できること
* 不正ログでは`None`を返すこと
* 正常なログファイルを読み込めること
* 正常ログと不正ログを分離できること
* 存在しないファイルを正しく処理できること
* CSVへ解析結果を保存できること

現在のテスト結果：

```text
6 passed
```

## 設計上の判断

### ログレベルを自動取得する

`INFO`、`ERROR`、`WARNING`などをプログラム側で固定していません。

各ログ行の3番目の要素をログレベルとして取得することで、

```text
DEBUG
CRITICAL
```

など、新しいログレベルが入力された場合でも、基本的にはコードを変更せず扱えるようにしています。

### ファイル不存在と不正ログ行を分けて扱う

入力ファイルそのものが存在しない場合は、解析するデータがないため処理を中断します。

一方で、1行だけ形式が壊れている場合は、他の正常ログまで解析不能にする必要はないと判断しています。

そのため、

```text
ファイルなし
→ 全体を中断

不正ログ行
→ その行だけ除外
→ 残りは解析続行
```

という設計にしています。

### ログ行全体ではなくLEVEL欄を確認する

例えば、

```text
2026-09-11 10:03:00 ERROR Failed to read INFO config
```

というログに対して、

```python
if "INFO" in log:
```

のように行全体を検索すると、誤って`INFO`ログとして扱ってしまいます。

そのため、

```text
YYYY-MM-DD HH:MM:SS LEVEL message
```

という入力仕様に従い、実際のLEVEL欄だけを確認しています。

## 現在の制限事項

* ログ形式は所定の位置形式を前提としている
* 日付・時刻そのものが正しい形式かまでは検証していない
* 複数行にまたがるログやスタックトレースには未対応
* 入力ファイルのパスは現在`main.py`内に固定している
* コマンドライン引数からファイルを指定する機能は未実装

## 今後の改善候補

* コマンドライン引数から入力・出力ファイルを指定
* 日付・時刻を含めたログ形式の厳密な検証
* 複数のログ形式への対応
* 件数だけを表示するサマリー機能
* JSON形式での出力
* 必要に応じた内部データ構造のリファクタリング
